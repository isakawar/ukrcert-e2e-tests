> Скопіюй усе нижче лінії в агента, що працює в `qa-base` і має QA Sphere MCP.
> Якщо кейси в автотестах змінились — спершу `npm run qasphere:export` у e2e-ukr-cert, щоб оновити вхідний файл.

## Задача: завести в QA Sphere кейси автотестів «Іноземні користувачі (Канада)» для УкрСерту

Продукт — УкрСерт (`qa-base/products/ukrcert/`), тенант `https://rg.eu1.qasphere.com`.
Є e2e-проєкт з автотестами (Playwright): `/Users/vladbilobrov/Documents/e2e-ukr-cert`. Автотести прив'язуються до кейсів QA Sphere через мапінг «назва тесту → номер кейсу», і після кожного прогону самі створюють тест-ран з результатами. Твоє завдання — створити кейси і записати цей мапінг.

### Вхідні дані (єдине джерело правди)

`/Users/vladbilobrov/Documents/e2e-ukr-cert/qasphere/cases-to-create.json` — 46 кейсів у потрібному порядку. Для кожного: `title`, `folderPath`, `type`, `priority`, `tags`, `precondition`, `steps`, `requirements` — це вже готові аргументи для `create_test_case` (HTML у полях — навмисно).

**`title` не змінювати ні на символ** (лапки «», апостроф ’, тире) — саме за ним автотест знаходить свій кейс. Кроки й передумови теж не перефразовувати.

### Кроки

1. **Проєкт.** Визнач код проєкту УкрСерту в QA Sphere (`list_projects` / `get_project`). Якщо проєкту немає або є кілька кандидатів — зупинись і запитай мене. Проєкт самостійно не створюй.
2. **Дублікати.** Перевір, чи немає вже папки «Іноземні користувачі (Канада)» з кейсами. Якщо є — зіставляй за точним `title`: наявні не створюй повторно, а використай їхній `seq` у мапінгу; створи лише відсутні.
3. **Папки.** Одним `upsert_folders` створи:
   - корінь `["Іноземні користувачі (Канада)"]` з коментарем:
     `<p>Автотести e2e (Playwright) для реєстрації, модерації, входу за кодом та іспитів іноземних користувачів. Кейси підтримуються з репозиторію e2e-ukr-cert (qasphere/catalog.json); тест-рани з результатами створюються автоматично після прогону автотестів.</p>`
   - усі унікальні `folderPath` з файлу (8 підпапок), `comment: null`.
   Запам'ятай ID листової папки для кожного `folderPath`.
4. **Кейси.** Для кожного елемента `cases` у порядку файлу — `create_test_case`:
   `projectCode`, `title`, `type: "standalone"`, `folderId` (листова папка його `folderPath`), `priority`, `tags`, `precondition`, `steps`, `requirements`, `pos` — порядковий номер кейсу всередині його папки (з 0), `isDraft: false`.
   З відповіді візьми `seq` (номер у маркері `<CODE>-<seq>` і в URL `/tcase/<seq>`).
   Якщо якийсь виклик падає — не зупиняйся на всіх, збери помилки і продовж.
5. **Мапінг.** Перезапиши файл `/Users/vladbilobrov/Documents/e2e-ukr-cert/qasphere/cases.json` рівно в такому форматі (ключі — `title` без змін, значення — `seq` числом, ключі за алфавітом):
   ```json
   {
     "_doc": "Назва тесту → номер кейсу в QA Sphere. Комітити в git.",
     "projectCode": "<CODE>",
     "baseUrl": "https://rg.eu1.qasphere.com",
     "cases": {
       "<title>": <seq>
     }
   }
   ```
6. **Перевірка.** У `cases` рівно 46 записів; вибірково відкрий 3–4 кейси через `get_test_case` (`<CODE>-<seq>`) — назва, папка, кроки на місці.
7. **qa-base.** У `qa-base/products/ukrcert/` заповни розділ QA Sphere (`Project code`, `Default folder ID` — ID кореневої папки) і середовище dev: `https://lms-exam-foreign-dev.raccoongang.com` (флоу іноземних користувачів; сам емулює закордонний IP). У «Модулі / фічі» додай як пропозицію: REG — реєстрація іноземця, MOD — модерація документа, AUTH — активація та вхід за кодом, EXAM — реєстрація на іспит і пункти тестування, ADMIT — допуск і проходження іспиту, PROFILE — профіль і заміна документа, REGR — регресія українського флоу.

### Чого не робити

- Не створюй тест-ран і не став результатів — рани з результатами створюють самі автотести.
- Не змінюй `cases-to-create.json` і назви кейсів.
- Не записуй токени/ключі в жодні файли.

### Звіт мені

Код проєкту, посилання на кореневу папку, скільки кейсів створено / використано наявних, список помилок (якщо були).
